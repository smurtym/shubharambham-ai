# Data Model: Infrastructure and Tooling Setup

**Feature**: 001-infrastructure-tooling-setup  
**Created**: 2026-03-14

---

## Overview

This is an infrastructure feature with no persistent application data model. There are no
database tables, user records, or domain entities. The "data" in this feature consists of:

1. **Ephemeris data files** — static binary data files consumed at WASM runtime
2. **WASM module outputs** — build artifacts, not application data
3. **A single computed value** — the Sun's ecliptic longitude returned from the WASM export

---

## Ephemeris Data Files

These are read-only binary input files produced externally by Astrodienst. They are not
modelled as application entities; they are build/runtime prerequisites.

| File | Virtual FS path | Size (approx) | Purpose |
|------|----------------|---------------|---------|
| `semo_18.se1` | `/ephe/semo_18.se1` | ~5 MB | Moon position data (required for full Vedic chart in future features) |
| `sepl_18.se1` | `/ephe/sepl_18.se1` | ~10 MB | Planet position data (Sun, Mars, Jupiter, etc.) |

**Access pattern**: Loaded once at WASM module init via Emscripten `--preload-file`; read
randomly by swisseph C library during `swe_calc()` calls. Never written to.

---

## Computed Value: Sun Longitude

The sole output of this feature's WASM API is an `f64` scalar.

| Field | Type | Unit | Range | Notes |
|-------|------|------|-------|-------|
| `sun_longitude` | `f64` | Degrees | 0.0 – 360.0 | Tropical (no ayanamsha); error sentinel: −1.0 |

No state is retained between calls. The function is pure and stateless given the hard-coded
input date (J2000.0).

---

## Build Artifacts

Build outputs placed in `dist/` are not application data but are listed here for clarity:

| Artifact | Type | Description |
|----------|------|-------------|
| `astro.wasm` | Binary | Compiled WASM module |
| `astro.js` | Text | Emscripten JS glue (module loader, FS setup, exports) |
| `astro.data` | Binary | Preloaded ephemeris data bundle (generated by emcc) |
| `index.html` | Text | Static web page |
| `style.css` | Text | Minimal stylesheet |

## Future Model Notes

Subsequent features (horoscope calculation) will introduce domain entities such as
`BirthData` (date, time, place) and `HoroscopeResult` (planet positions, house cusps).
Those will be defined in their own `data-model.md` files. This feature establishes no
constraints on their shape.
